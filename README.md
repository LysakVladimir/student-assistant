# StudyPilot — универсальный интеллектуальный ассистент студента

MVP учебного проекта: Telegram-бот + Telegram Mini App (React) + FastAPI + MySQL + ИИ-агент с инструментами.

## Что реализовано
- Профиль пользователя, связанный с Telegram ID.
- REST API и проверка `Telegram.WebApp.initData` для Mini App.
- Редактирование расписания: добавление/просмотр занятий, предмет, тип, аудитория, время, корпус, чётность недели.
- Парсинг официального расписания ГУАП по номеру группы (вкладка «Расписание» Mini App) с сохранением в расписание пользователя.
- Понятие чётной/нечётной недели: занятия можно привязать к чётной/нечётной/обеим неделям, план дня фильтруется по текущей неделе.
- Контекстный рюкзак: правила вещей по типу занятия и пользовательские постоянные вещи.
- План на сегодня/завтра: расписание, список вещей, ориентировочное время выхода.
- Погодный адаптер Open-Meteo (не требует ключа) и базовый расчёт выхода.
- Окна между занятиями: обнаружение свободных промежутков.
- ИИ-агент: локально маршрутизирует обычный диалог, расписание/погоду и RAG; если LLM недоступна, сохраняются детерминированные функции и поиск по исходным сообщениям.
- Telegram AI-агент: подключение групп, пассивный анализ, долговременная память, поиск/RAG, задачи, решения, мониторинг и сводки.
- Docker Compose для локального запуска, MySQL, backend, bot, frontend.
- Swagger/OpenAPI, health-check и базовые тесты.

## Важно: границы MVP
Это стартовый каркас для курсовой, а не production-сервис. Для точного маршрута, пробок и прибытия транспорта нужны API конкретного города и/или GTFS-данные. В этой версии маршрут — пользовательская оценка времени в пути; пробки моделируются коэффициентом. Импорт фото/страниц расписания, полноценная карта и продвинутая авторизация/администрирование оставлены как следующие итерации. Не сообщайте пользователю, что автобус точно прибудет в определённое время, если нет подключённого источника реального времени.

## Стек
- Python 3.12, FastAPI, SQLAlchemy, PyMySQL, aiogram 3, APScheduler
- MySQL 8
- React + Vite + Telegram WebApp SDK
- Polza.ai через OpenAI-compatible API; Gemini сохранён для совместимости и мультимедиа
- Open-Meteo для погоды

## Быстрый запуск
1. Установите Docker Desktop.
2. Создайте Telegram-бота через `@BotFather`, скопируйте токен.
3. Скопируйте `.env.example` в `.env`, замените все `CHANGE_ME_*`, задайте `TELEGRAM_BOT_TOKEN` и безопасные MySQL/внутренние секреты. Для рекомендуемой AI-конфигурации задайте `POLZA_API_KEY`; Gemini нужен только как необязательный media fallback.
4. В каталоге проекта выполните:
   ```bash
   docker compose up --build
   ```
5. API: http://localhost:8000/docs ; frontend: http://localhost:5173
6. В Telegram отправьте боту `/start`.

### Локальный запуск без Docker
Требуются Python 3.12 и Node.js 20.19+.
```bash
cd backend
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```
В другом терминале:
```bash
cd bot
pip install -r requirements.txt
python main.py
```
Frontend:
```bash
cd frontend
npm install
npm run dev -- --host 0.0.0.0
```
Для локального запуска без Docker задайте `DATABASE_URL` в `.env` на доступную MySQL. Бот и backend читают один `.env` из корня проекта.

## Подключение Mini App к Telegram
Для разработки интерфейс доступен на `localhost:5173`, но Telegram Mini App обычно требует HTTPS-домен, зарегистрированный у BotFather. Для демонстрации:
1. Разверните frontend на HTTPS-хостинге (например, Cloudflare Pages).
2. Разверните backend на HTTPS-хостинге и задайте `VITE_API_URL`.
3. В BotFather настройте Menu Button / Web App URL.
4. В `.env` backend укажите `TELEGRAM_BOT_TOKEN`, чтобы проверка `initData` работала.
5. Не используйте `VITE_DEV_AUTH=true` в публичном окружении.

## Как пользоваться
- `/start` — регистрация и краткая инструкция.
- `/today` — план на сегодня.
- `/tomorrow` — план на завтра.
- `/bag` — список вещей на ближайшие занятия.
- `/windows` — свободные окна между парами.
- `/weather` — погода по городу из настроек (город вводится на русском).
- `/route` — оценка времени выхода.
- `/settings` — текущие настройки.
- `/help` — помощь.
- Mini App — редактирование расписания, правил рюкзака и параметров дороги.

При первом запуске добавьте занятия в Mini App. Время занятий вводится в локальном времени пользователя. В настройках укажите адрес/название корпуса и примерное время пути и сборов.

## ИИ-агент
Агент не должен придумывать расписание или вычислять критичное время. Backend до обращения к модели разделяет обычный разговор, запросы расписания/погоды и поиск по групповой памяти. Расписание и погода вычисляются обычным кодом без принудительного tool calling; свободный диалог отправляется модели без tools; RAG получает только сообщения доступных пользователю групп. При отсутствии API-ключа продолжают работать расписание, сохранение сообщений, лексический поиск и безопасный fallback.

Рекомендуемая конфигурация использует Polza.ai: Flash для пакетного фонового анализа и Pro только для сложных запросов. Без ключа сохраняются сообщения и работают детерминированные функции/локальный поиск.

### Групповые чаты и память

1. Отключите Privacy Mode бота в BotFather, если бот должен получать обычные сообщения группы.
2. Добавьте бота в группу и выдайте права на чтение сообщений.
3. Администратор выполняет `/ai_on`. Бот публикует уведомление об обработке и начинает сохранять только новые доступные сообщения.
4. Каждый пользователь, которому нужен личный доступ к данным группы, выполняет в ней `/ai_join`.
5. В личном чате используйте `/ai`, `/groups`, `/tasks` или задайте вопрос естественным языком.
6. Интерактивные ответы в группе по умолчанию выключены. Администратор включает их командой `/ai_interactive on`; бот отвечает только на упоминание или reply.

Поддерживаются текст, reply, редактирование, голос, изображения и документы. Текст сначала сохраняется, затем сообщения одного чата обрабатываются пакетами через persistent-очередь. Изображения может анализировать DeepSeek V4 Flash; для аудио при Polza-конфигурации используется прежний Gemini только если отдельно задан `GEMINI_API_KEY`. Без мультимодального ключа сохраняются метаданные и подпись. Telegram Bot API не отдаёт сообщения до подключения бота и не сообщает боту об обычном удалении сообщения. Старую историю можно импортировать JSON-экспортом Telegram через `POST /api/agent/chats/{chat_id}/import` (до 10 000 сообщений за запрос).

Полнотекстовый поиск работает локально. Для Polza используются многоязычные embeddings `baai/bge-m3`; при недоступности модели используется лексический поиск и безопасный ответ со ссылками. Каждая выборка сначала ограничивается таблицей доступа пользователя, поэтому данные чужого чата не попадают в RAG-контекст. Администратор группы может отдельно запретить передачу её содержимого внешнему AI.

### Провайдеры моделей

`AI_PROVIDER` принимает `polza`, `gemini`, `openai`, `openrouter`, `anthropic` или `local`. Polza использует `POLZA_BASE_URL=https://polza.ai/api/v1` и серверный `POLZA_API_KEY`.

- `AI_BACKGROUND_MODEL=deepseek/deepseek-v4-flash` — пакеты сообщений, извлечение фактов, промежуточные сводки.
- `AI_PRIMARY_MODEL=deepseek/deepseek-v4-pro` — сложный RAG, несколько чатов, многошаговые инструменты.
- `/ai_mode economy|auto|quality` или Mini App переключают реальный маршрутизатор, а не только подпись интерфейса.
- Все обращения проходят через `ai_runtime.py`: бюджет, rate limit, параллелизм, журнал модели/токенов/стоимости/времени/ошибки.
- HTTP 402 не повторяется: persistent circuit breaker приостанавливает платные вызовы, а необработанные сообщения остаются в очереди.

Подробная самостоятельная проверка: [USER_TESTING_GUIDE.md](USER_TESTING_GUIDE.md). Фактические результаты этой разработки: [TESTING_REPORT.md](TESTING_REPORT.md).

## Переменные окружения
См. `.env.example` — это полный безопасный шаблон без персональных значений. Минимально необходимы:

- `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` и HTTPS `WEBAPP_URL` для Telegram;
- `MYSQL_DATABASE`, `MYSQL_USER`, `MYSQL_PASSWORD`, `MYSQL_ROOT_PASSWORD` для Docker MySQL;
- две независимые длинные строки `APP_SECRET` и `INTERNAL_API_TOKEN`;
- `POLZA_API_KEY`, модели Flash/Pro/BGE-M3 и AI-лимиты, если включён внешний AI;
- `DEV_AUTH=false` и `VITE_DEV_AUTH=false` во всех публичных окружениях.

`AI_ADMIN_TELEGRAM_ID` и `VITE_DEV_TELEGRAM_ID` оставлены пустыми в шаблоне: это персональные идентификаторы. Рабочий `.env` никогда не должен добавляться в Git.

## Безопасная публикация

- Перед коммитом выполните `git status --ignored`, `git diff --check` и проверьте список `git ls-files --cached --others --exclude-standard`.
- Не публикуйте `.env`, базы `*.db`/`*.sqlite*`, SQL-дампы, Telegram exports, generation logs Polza и локальные каталоги `.venv`, `node_modules`, `dist`, `data`.
- Если секрет когда-либо попал в коммит, одного удаления из текущей версии недостаточно: отзовите секрет и очистите историю отдельной согласованной процедурой.
- Внешние лимиты Polza и отдельный API-ключ проекта остаются обязательной защитой даже при внутренних лимитах StudyPilot.

## API (основные маршруты)
- `GET /health`
- `GET /api/me`
- `PATCH /api/me`
- `GET/POST /api/lessons`
- `DELETE /api/lessons/{lesson_id}`
- `POST /api/lessons/parse` — спарсить расписание ГУАП по номеру группы
- `GET /api/weather` — погода по городу пользователя (Open-Meteo)
- `GET /api/week-parity` — текущая чётность недели (odd/even)
- `GET/POST /api/bag-rules`
- `DELETE /api/bag-rules/{rule_id}`
- `GET /api/plan?day=today|tomorrow`
- `GET /api/windows?day=today|tomorrow`
- `POST /api/agent/chat`
- `GET /api/agent/chats`, `PATCH /api/agent/chats/{id}`
- `GET /api/agent/search`, `GET /api/agent/facts`
- `GET/POST/DELETE /api/agent/monitors`
- `DELETE /api/agent/chats/{id}/data`
- `POST /api/agent/chats/{id}/import`

Mini App передаёт `X-Telegram-Init-Data`. Проверка подписи выполняется backend по официальной схеме Telegram. Для ручного тестирования API можно включить `DEV_AUTH=true` и передать `X-Dev-Telegram-Id`, но только в локальной среде.

## План развития команды
1. Импорт расписания из CSV/Excel/ICS.
2. Реальные маршруты и транспорт (OSRM/GTFS/городской API).
3. Расширить расписание тихих часов и добавить отдельный worker при росте нагрузки.
4. Расширить agent tool-calling и покрыть реальными Telegram/MySQL end-to-end сценариями.
5. Карта, анализ мест для еды/учёбы, бюджет.
6. CI, миграции Alembic, мониторинг и защита персональных данных.
