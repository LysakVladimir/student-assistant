# Диагностика и исправление AI-агента StudyPilot

Дата: 22 ноября 2026. Среда разработки: Windows, `C:\Projects\student-assistant`.

Статусы: PASS — проверка выполнена; FAIL — ошибка подтверждена; BLOCKED — недоступна внешняя зависимость; NOT TESTED — после исправления проверка не запускалась.

## Итог

Основной дефект воспроизведён по коду и трём реальным журналам Polza. Любая свободная реплика отправлялась в DeepSeek V4 Flash с двумя несвязанными инструментами и `toolChoice: required`. Polza возвращала `BAD_GATEWAY: Провайдер вернул некорректный вызов инструмента`. После исключения маршрут падал в локальный fallback расписания, поэтому вопросы про AI, фразы «спасибо» и групповые факты превращались в план занятий или рюкзак.

Маршрут исправлен без замены архитектуры: свободный диалог, расписание/погода и групповая память теперь разделяются до обращения к модели. Обычный диалог не получает tools; расписание и погода вызываются детерминированно; RAG использует исходные сообщения и `memory_facts`.

## Исправленные файлы

- `backend/app/agent.py` — единый классификатор намерений, обычный диалог без tools, контекст беседы, deterministic plan/weather, RAG по сообщениям и фактам, состояние очереди.
- `backend/app/memory.py` — поиск `memory_facts`, pending-count, локальный fallback без embeddings, reliability guard для слухов.
- `backend/app/provider_client.py` — отдельная ошибка `InvalidToolCall`, отсутствие retry для некорректного tool call.
- `backend/app/ai_runtime.py` — circuit breaker после исчерпания повторов обычной provider-ошибки.
- `bot/main.py` — все личные тексты идут в backend-router; group mention/reply/text_mention; priority; явный ответ при ошибке.
- `bot/message_routing.py` — тестируемые Telegram routing helpers и очистка Markdown.
- `tests/test_agent_memory.py`, `tests/test_ai_routing.py`, `tests/test_bot_message_routing.py`, `tests/test_agent_api_integration.py`, `tests/conftest.py` — регрессии реальных сценариев и интеграционный pipeline.
- `USER_TESTING_GUIDE.md`, `TESTING_REPORT.md`, `AI_DEBUG_REPORT.md` — актуальная проверка и ограничения.

## Известные ограничения

1. Docker, MySQL volume и Telegram polling не доступны в текущем окружении.
2. 138 предупреждений относятся преимущественно к будущему удалению `datetime.utcnow()` в Python 3.13. Это не ломает тесты, но требует отдельной timezone-aware миграции.
3. `main.py` применяет миграции при импорте. Интеграционный тест изолирует этот side effect и использует SQLite; production lifecycle не менялся в рамках этой задачи.
4. Telegram не отдаёт боту произвольную старую историю. Анализ начинается после `/ai_on`, старые данные доступны только через JSON import.
5. Реальный ответ модели может отличаться формулировкой. Источники и статусы достоверности необходимо проверять в UI.

## Решение по tool calling

Простая замена `required` на `auto` не использована как единственная мера. В production-маршруте модель больше не выбирает между планом и погодой: intent определяется локально, аргументы валидируются кодом, а обычные реплики отправляются как text-only chat. Это дешевле и устраняет несовместимость Flash. Низкоуровневый клиент сохраняет совместимость с tools для будущих явно подтверждённых моделей, но текущий пользовательский маршрут от неё не зависит.
